# 手部画法正确度评估

> **本文件只有中文版。** 这是原始工作日志，按时间顺序记录，保留原样以作为
> `RESULTS` / `FINDINGS` 背后的证据链。其余文档均为中英双语。
>
> **This file is Chinese only.** It is the raw chronological log, kept as the
> evidence trail behind `RESULTS` / `FINDINGS`. Every other doc is bilingual.
>
> 英文入口 / English entry: [README](../README.md) · [RESULTS](RESULTS.md) ·
> [FINDINGS](FINDINGS.md)

判断 AI 生成的动漫插画中，**手部画法是否正确**。
输入一只手的图像，输出 0~1 的质量分（越高越像正常的手）。

---

## 一、要解决的问题

AI 出图（尤其是 SD / XL / IL / Pony 等较早期模型）经常把手画错：
手指数量不对、融合粘连、关节错位、比例失调、细长如蜘蛛腿。人工逐张筛图成本高。

### 与「手部检测」的区别（两个不同的任务）

| 任务 | 回答的问题 | 用什么 |
|---|---|---|
| **手部检测** | 这是不是一只手？在哪里？ | `hand_yolov8s`（11M 参数，21MB） |
| **手部正确度评估** | 这只手**画得好不好**？ | 本项目 |

**实测证据**：`hand_yolov8` 的检测置信度对「画得好不好」的 **AUC 仅 0.5686**（接近抛硬币）。
它能判断"是不是手"，但**完全不判断"画得对不对"**——这正是本项目的价值。

---

## 二、方法论：三层捷径防御 ★最重要

在数据规模小、来源杂的情况下，模型极易学到**捷径**而非真实能力。
本项目**三次**撞上捷径，每次都靠诊断发现并修掉。

### 捷径一：背景色差异

最初基线拿到 **AUC 0.9952**，看起来完美。但检查发现：

```
good 组（从素材裁的手）    近白像素占比  7.7%   亮度 168.4
bad  组（IL 白背景生成）   近白像素占比 43.7%   亮度 221.2
────────────────────────────────────────────────────────
仅用「近白占比」这一个标量的 AUC = 0.9733
```

**模型学的是"背景是白还是粉"，与手画得好不好毫无关系。**

更糟的是：当时 CLIP 权重因格式不匹配没加载成功（`missing=686`，实为随机初始化），
**随机特征也拿到 0.995** —— 说明这个基线完全是捷径，与模型无关。

**修法**：good 与 bad 必须来自**同一来源**（同模型、同构图、同背景）。

### 捷径二：手势类别

改用同源数据后，分层诊断发现：

```
总体 AUC            0.7323
各手势内平均         0.6039    ← 明显低于总体
7 类手势分类准确率    0.7042    ← 特征里手势信息极强
```

原因：IL 在某些手势上**系统性画错**，导致「手势 ↔ 质量」天然绑定。

```
open hand, spread fingers   32 bad / 0 good   ← IL 根本画不对
own hands together          10 bad / 0 good
v sign                      16 good / 3 bad   ← 这个它很擅长
```

模型学到"看到张开的手就判 bad"，在这批数据上几乎不会错，但**换个模型就完全失效**。

**修法**：用**另一个模型（Anima）补生成缺失组合**（实测"新模型画对的多"确实成立）：

```
open hand          IL 0g/32b  + Anima 23g/18b  →  27g / 69b  ✓
own hands together IL 0g/10b  + Anima 40g/23b  →  37g / 26b  ✓
```

矩阵补齐后，模型无法再靠手势蒙分。

### 捷径三：画风 / 模型指纹

IL 与 Anima 画风差异明显（暖肤色简洁 vs 冷色调带装饰）。
若 good 全来自一个模型、bad 全来自另一个，模型会学成"辨认模型"。

**防御手段**：**评估时必须按模型分层**：

```
按模型分层实测：
  Anima  AUC 0.876
  IL     AUC 0.777
  ── 模型内平均 0.8268    ← 若靠认模型蒙分，这里会塌到 0.5
```

### 评估铁律

> **只算总体 AUC 会掩盖捷径。必须同时做「按手势分层」与「按模型分层」，
> 两者内部都有判别力，才算真实能力。**

## 四、模型

### 4.1 CLIP 基线

**特征提取器**：本地 `CLIP-ViT-H-14-laion2B-s32B-b79K.safetensors`（2.4GB，632M 参数）

> ⚠️ **深坑**：该权重是 HuggingFace transformers 格式（Q/K/V 分离为
> `q_proj`/`k_proj`/`v_proj`），而 open_clip 要求**合并**的 `in_proj_weight`。
> 用 open_clip 加载会 `missing=686`，**静默变成随机初始化**，
> 且因数据存在捷径而拿到虚高的 0.9952，**掩盖了问题**。
>
> **正确解法**：`transformers.CLIPVisionModel` + 剥掉 `vision_model.` 前缀
> ```python
> sd = {k[len("vision_model."):]: v
>       for k, v in load_file(CLIP_W).items()
>       if k.startswith("vision_model.")}
> model = CLIPVisionModel(cfg)          # hidden=1280, layers=32, heads=16, patch=14
> model.load_state_dict(sd, strict=False)   # → missing=0
> ```

| | 线性探测 | 微调 |
|---|---|---|
| 做法 | 冻结 CLIP + 逻辑回归 | 解冻最后 4/32 block + post_layernorm |
| 可训练参数 | 1281 | 78.7M / 630.8M |
| 耗时 | ~40 秒 | ~5 分钟 |

**必须说明的定位问题**：CLIP 方案中**自训部分仅占整体 0.0002%**，
本质是 **linear probe**（线性探测），不是独立模型，且 2.4GB 底座
在 8GB 卡上与 ComfyUI 抢显存。

### 4.2 小模型（真正自有、可独立运行）

| 模型 | 参数量（实测） | 体积（实测 .pt） |
|---|---|---|
| ResNet-18 | 11.19M | 44.8 MB |
| ResNet-34 | 21.30M | 85.3 MB |
| EfficientNet-B0 | 4.05M | 16.3 MB |
| MobileNetV3-Small | 1.53M | 6.2 MB |

> 早先这里按"名字上写的参数量"填了 11.7M / 5.3M / 2.5M，
> 后来用 `sum(v.numel())` 实测才发现 EfficientNet-B0 和 MobileNetV3-Small
> 比标称小得多 —— 因为两者都换掉了分类头，且 torchvision 的实现与论文数字不同。
> 上表以实测为准。最终交付的集成是 ResNet-18 + EfficientNet-B0，**共 61 MB**。

**训练策略**：ImageNet 预训练 + 分层 5 折（分层键 = 模型 × 手势）
+ 类别权重 + 早停 + **ONNX 导出**（脱离 PyTorch 部署）

### 4.3 训练配置（两者一致）

```python
数据增强：±12° 旋转 / 0.85~1.0 缩放裁剪 / 亮度·对比度抖动
         + HSV 色相饱和度抖动 / 15% 概率转灰度   ← 针对背景色捷径，见 11.7
         ⚠️ 绝不水平翻转 —— 左右手解剖结构不同，翻转会破坏标签语义
损失：    BCEWithLogitsLoss + 类别权重（平衡偏斜手势）
早停：    验证 AUC 连续若干 epoch 不升
随机种子：固定（--seed 42）—— 不固定的话同一份数据两次跑的 OOF 能差 0.01 以上
```

## 五、工程踩坑记录

都是实际发生并造成过损失的：

| 问题 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **GPU 驱动重置** | 33 分钟毫无进展、**不报错**、日志停在开头 | `best_state` 克隆全部 630.8M 参数 = 2.52GB（其中 552M 冻结参数永不改变）→ 显存 94.5% → 触发 TDR | 只存可训练参数 + offload 到 CPU（315MB） |
| **单步 28 秒** | 远慢于理论 1.5 秒 | `allow_tf32 = False`，走 FP32 CUDA 核 | `allow_tf32 = True` → **0.84 秒/步** |
| **进度不可见** | 出问题无从定位 | 日志用 `\r` + `end=""`，不换行不 flush | 每 epoch 一行 `\n` 日志，含 AUC 与显存 |
| **每折重复加载** | 3 次读 2.4GB + 折间显存尖峰 | 折循环内 `build_model()` | 权重只读一次，跨折复用 |
| **轮询轰炸** | 生成速度 8.7s/张 → 32s/张 | 每 3 秒对 300 个任务各查一次 `/history`（≈100 req/s） | 改用单次 `/queue` 轮询，20 秒一次 |
| **502 中断** | 395 张生成任务在第 3 张整体退出 | 无重试，单张失败抛异常终止全流程 | POST 加重试 + 单张失败 `continue` |
| **去重误杀** | 素材 174 只手被砍到 21 只 | 8×8 aHash 对"同构图不同表情"给出**相同**哈希 | 改用**文件名归一化**去重 |
| **输入尺寸过大** | inpaint 单次 14 分 40 秒 | 拿 2764×4148 原图做 inpaint，全分辨率跑 20 步 | 裁手部区域 → 长边 768 → 单次 17 秒（**快 53 倍**） |
| **C 盘告急** | C 盘仅剩 15GB | pip 缓存、模型下载默认写 C 盘 | venv 与产物全放 D 盘；复用 ComfyUI 的 Python 实现**零安装** |

### 显存占用的铁律

> **任何时候都只能有一个进程占用 GPU。**
>
> 本项目两次显存事故都源于此：一次是生成时另开进程跑 YOLO，
> 一次是 inpaint 时同进程持有 SDPose（2GB）。
> 正确做法是**阶段分离**：先做完 A 阶段并释放，再进入 B 阶段。

## 六、走过但已放弃的路线

| 方案 | 结论 | 原因 |
|---|---|---|
| **MediaPipe 提关键点** | ❌ | 动漫手检出率仅 **50.5%**；检出的关键点**位置也是错的**；置信度对错都在 0.9+，**完全无判别力** |
| **SDPose-OOD（整图）** | ✅ | 好手 score 0.70~0.89 / 无手 0.11~0.15，判别力好 |
| **SDPose（手部裁剪图）** | ❌ | **检出率仅 8%**（40 只检出 3 只），AUC 0.53~0.58。<br>**根因**：SDPose 是 whole-body 模型，靠人体结构推断手；裁掉身体后失效 |
| **自研骨架模型** | ❌ | 需给 336 只手各标 21 个关键点 = **7,056 个点坐标**，且要像素级精度，成本不可承受 |
| **inpaint 合成坏手（5 种破坏）** | ❌ | 彩色噪声→"彩色异物"；旋转→模型直接扶正；替换手→仅"手指变细长"；肉块→模型扶正或留肉块。**合成崩坏形态都不真实** |
| **素材手 vs 生成手当 good/bad** | ❌ | 单标量"近白占比"就 AUC 0.973 |

### 骨架路线的根本障碍

```
我们的模型输入 = 裁剪的手
骨架提取需要  = 完整的人    ← SDPose 检出率仅 8%
        ↓
两者根本矛盾（循环依赖成立）
```

SDPose 在管线中**保留原有角色**（数据构建期提关键点做 inpaint 遮罩，
那里输入是整图，工作正常），但**不作为模型特征**。

## 九、已知边界

1. **跨模型泛化**：训练集只含 IL / Anima / 用户素材；第十一节的跨模型测试集
   是为此专门补的（FLUX.2 + Krea2，训练时完全未见过）
2. **小样本手势不可靠**：15~30 只的手势，换一次 fold 划分 AUC 可浮动 0.15
3. **定位是辅助工具**：应作"辅助筛图"，而非"自动判废"
4. **标注一致性风险**：连标数百张后标准可能漂移（曾出现数据增加反而掉分）
5. **标注噪声是本方案的真实上限** ★（第十六节有量化）
   三级盲测显示：我标 bad 的样本里只有 **2%** 能被独立复现为客观画错，
   **81% 被判为 fine**，两套标注在干净子集上的 **kappa = −0.003**。
   原来写的"与另一个人的一致率大概七八成"是低估了问题 —— 实际接近零。
   后果：AUC 的**绝对值**不可当真，但**相对比较**仍然成立
   （同一批噪声标签下比较 CLIP 与小模型、以及比较跨模型前后，结论有效）。
   要突破这个上限，需要多人独立标注 + 交集/一致率统计，不是模型能解决的。

   再加"好样本"边际收益已经很低。
   真正的提升点转向**修标签定义**，见第十五节 15.4。
4. **骨架特征**：若未来出现能在"孤立手"上可靠工作的关键点模型，可重新评估

## 十一、第四次扩增与跨模型评测

### 11.1 目的

前三轮的结论是"**瓶颈是数据不是模型**"：每折 AUC 波动 0.15，因为
`clenched hand` 只有 12 只、`holding object` 14 只，交叉验证每折里
只剩 2~3 只，AUC 完全由噪声决定。所以这一轮的目标是把每个手势
的 good/bad 都补到 50 以上。

### 11.2 生成 + 裁手（`_expand_gen.py` + `_recover_hands.py`）

IL / Anima 交替生成 395 张（弱项手势多给量），耗时 135 分钟，0 失败。

**但裁手暴露了一个大问题**：`hand_yolov8s` 有 126 张（32%）一只都没检出。
按手势拆开看，漏检是**系统性**的，不是随机：

| 手势 | 漏检率 | 原因 |
|---|---|---|
| clenched hand | **82%** | 握拳不是"张开的手"，检测器训练集里几乎没有 |
| thumbs up | 60% | 同上，手指并拢 |
| pointing | 33% | |
| holding object | 27% | 手被物体遮挡 |

这直接砍在最缺样本的手势上。处理办法是**只对零检出的图**降阈值重试
（conf 0.25 → 0.10 → 0.05，imgsz 1280 → 1536，且**只取最可信的一个框**，
避免把袖子/下巴当手混进来），找回 74 只，总数 446 → 520。

> 这条印证了用户的判断："到了后期 hand_yolov8 可以被优化掉"。
> 它现在是数据管线的短板 —— 不是能力的加分项，而是漏检的来源。

### 11.3 ★ 一个意外且重要的发现：扩增几乎全是好样本

对 312 只做了人工标注，结果是 **284 good / 3 bad / 25 skip —— 97% 是 good**。

原因不难理解：`_expand_gen.py` 的模板里有
`masterpiece, best quality, ultra-detailed` + `hand focus`，
**等于要求模型拿出它最好的一面**。IL 在被逼着超水平发挥时，
手是真的画得不错的。

**这个发现改变了数据策略**：

- 它**解决了 good 缺口**：`thumbs up` 6→35、`hand on own chest` 6→30、
  `pointing` 11→46、`outstretched hand` 8→43。这些手势原先的问题
  就是"好样本太少"，补齐后每个手势 good 都 ≥26。
- 它**没有解决 bad 缺口**，反而放大了类别不平衡：
  `clenched hand` 仍然只有 3 个 bad、`v sign` 4 个、`holding object` 7 个。

训练集由此从 336 涨到 **623**（good 442 / bad 181，71% good）：

| 手势 | good | bad | 合计 |
|---|---|---|---|
| open hand, spread fingers | 48 | 69 | 117 |
| peace sign | 70 | 11 | 81 |
| own hands together | 49 | 26 | 75 |
| outstretched hand | 43 | 23 | 66 |
| pointing | 46 | 13 | 59 |
| holding object | 51 | **7** | 58 |
| v sign | 44 | **4** | 48 |
| thumbs up | 35 | 12 | 47 |
| hand on own chest | 30 | 13 | 43 |
| clenched hand | 26 | **3** | 29 |

**结论：想补 bad 样本，必须换一套"故意让它画错"的生成配方**，
不能指望在原来的高质量模板上多生成几张。这正是第十节第 2 条要做的事。

### 11.4 跨模型测试集（`_cross_gen.py`）

之前的评估全都在 IL + Anima 内部做交叉验证。问题是：同一个模型画的手
带着强烈的**模型指纹**（线条习惯、上色风格、指节画法），CNN 完全可以
靠指纹把 good/bad 分开，而不是真的看懂了手的结构。
我们此前自己诊断出的背景捷径（单一标量 AUC 0.973）就是同类问题。

用户给的线索更直接：

> 老模型（SD/XL/IL/Pony）经常画错手；新模型（FLUX/Qwen/Krea2/Anima）经常画对。

也就是说"**模型族**"和"标签"天然相关 —— 测试集若全是被训练过的模型，
AUC 里就掺着"认出这是 IL 画的"这种作弊分。

所以用两个**训练时绝不使用**的模型族生成测试集，复用用户自己仓库里的
现成 API 工作流（`input/Workflow/` 之外，取自 `ComfyUI/workflow/api/`）：

| 模型 | 架构 | 文本编码器 | VAE |
|---|---|---|---|
| `moodyDesireMix_v30` | FLUX.2（`double_blocks`） | `qwen_3_8b_fp8mixed` | `flux2-vae` |
| `krea2CatTower_v10TurboINT4Convrot` | Krea2（`blocks.*.attn.wq`，INT4 量化） | `qwen3vl_4b_fp8_scaled` | `qwen_image_vae` |

- 每个模型每个手势 6 张，共 120 张；提示词模板与训练集**逐字保持同一语义**
  （把 danbooru 标签换成自然语言，因为这两个模型吃自然语言更好），
  这样"模型族"成为唯一变量
- 裁手参数与训练集**完全一致**（conf 0.25 / imgsz 1280 / bbox×1.2 / 最小边 48px），
  避免引入新的分布差异
- 样本落在独立的 `_cross/` 目录，且 `_write_labels4.py` 里有**硬性防泄漏断言**：
  跨模型样本的 `hand_id` 一旦出现在训练集里就直接中止

从抽样看，FLUX.2 出的是**平涂赛璐璐 + 粗描边**，与 IL/Anima 的厚涂风格
差异极大 —— 这正是我们要的域偏移。

### 11.5 本轮修掉的两个 bug

1. **排序被静默覆盖**（`_label_batch3.py`）：
   加了"缺口优先"排序后，下一行原有的 `recs.sort(key=hand_id)` 把它
   覆盖掉了，导致排序完全没生效。因为标注编号一旦写进 `labels.json`
   就不能再改（改了全部错位），所以没有回退顺序，而是删掉死代码、
   并把"顺序不可再改"写进注释。
2. **全量重训轮数写错**（`_train_small.py`）：
   `epochs_final = max(12, int(np.mean([len(fold_best)]) * 3))` ——
   `len(fold_best)` 恒等于折数，`np.mean` 恒为 1，所以实际永远只训 12 轮。
   改成用各折最优轮次的均值 `np.mean(fold_ep)`。

### 11.6 评估方法（`_train_small.py --cross`）

输出四个层次的结果，缺一不可：

1. **域内交叉验证 OOF AUC** —— 与 CLIP 基线可直接对比
2. **按手势 AUC** —— 防止"整体好看但某个手势完全失效"
3. **按模型 AUC** —— 防止学到模型指纹
4. **★ 跨模型 AUC（训练时从未见过 FLUX.2 / Krea2）** —— 唯一能说明
   "真的看懂了手"而不是"背下了 IL 的画风"的证据

第 4 项是这一轮最重要的产出。

### 11.7 捷径复检（`_diag_shortcut2.py`）★

第四次扩增新增的 284 张**全部**用 `white background, simple background` 生成，
等于把背景又拉回单一化。项目早期正是栽在这条捷径上（当时"近白像素占比"
一个标量就能把素材和 IL 出图分开，AUC 0.973），所以必须复检。

对 623 只逐个算 6 个单标量，看它们各自能把 good/bad 分开到什么程度：

| 标量 | 全样本 | Anima 组内 | IL 组内 |
|---|---|---|---|
| 近白占比 | 0.623 | **0.757** | 0.527 |
| 平均亮度 | 0.639 | **0.727** | 0.520 |
| 平均饱和度 | 0.584 | 0.671 | 0.503 |
| 清晰度 | 0.656 | 0.548 | 0.553 |
| 画面尺寸 | 0.604 | **0.709** | 0.550 |
| 检测置信度 | 0.568 | 0.663 | 0.525 |

**结论分两半，都得说清楚：**

- **好消息**：全样本层面没有任何单标量能拿到高分（最高 0.656，对比早期的
  0.973），也就是说想拿分必须真的看手，没有一条"一个数字通关"的路。
- **坏消息**：捷径没有消失，只是**局部化**了。
  - 在 Anima 组内，"近白占比 / 平均亮度 / 画面尺寸"都能到 0.71~0.76 ——
    Anima 画坏手的那些图，背景更暗、更复杂。
  - 在 `own hands together` 手势内，"近白占比"单标量 AUC 高达 **0.905**。
    这直接意味着：此前该手势 0.87~0.955 的分手势 AUC **有一部分是背景贡献的**，
    不能全算作"看懂了手"。

**对应的处理**：在 `_train_small.py` 里加了针对性的颜色/背景增强 ——
15% 概率转灰度（直接抹掉全部颜色信息）、60% 概率做 HSV 色相/饱和度抖动、
50% 概率做对比度抖动。目的就是把这些颜色统计量打散，逼模型依赖形状。
（仍然**不做水平翻转** —— 左右手解剖不同，翻转会破坏标签语义。）

这个复检说明了一件事：**数据集层面"看起来压下去了"的捷径，
可能在子群组里依然活着**。只看整体 AUC 是查不出来的。

所有模型都**只在 IL / Anima 上训练**，跨模型测试集的模型族训练时从未出现。

### 12.2 各架构结果（776 只，固定种子 seed=42）

**为什么必须重跑**：第一轮结果里，同一架构两次跑的 OOF AUC 差到 0.01 以上，
跨模型误报率甚至从 84% 翻到 0%。原因是数据增强用的是**全局 numpy RNG，
没有被固定**。这种不可复现的结果不能作为结论 —— 详见第十四节。

| 架构 | 参数量 | 体积 | 域内 OOF AUC | 折间波动 | 跨模型误报@0.5 | 域内好手中位分 | 跨模型好手中位分 | 分数平移 |
|---|---|---|---|---|---|---|---|---|
| efficientnet_b0 | 4.05M | 16 MB | **0.8567** | 0.033 | 2.7% | 0.979 | 0.980 | +0.002 |
| resnet18 | 11.19M | 45 MB | 0.8330 | 0.024 | 1.3% | 0.967 | 0.985 | +0.018 |
| mobilenet_v3_small | 1.53M | 6 MB | 0.8289 | 0.027 | 1.3% | 0.989 | 1.000 | +0.011 |
| resnet34 | 21.30M | 85 MB | 0.8107 | 0.029 | 25.3% | 0.982 | 0.973 | −0.010 |
| resnet18（select=last，无选择偏差） | 11.19M | 45 MB | 0.8252 | 0.020 | 2.7% | 0.997 | 0.996 | −0.001 |
| **集成 r18+effnet_b0（交付）** | 15.24M | 61 MB | **0.8664** | — | **0.0%** | 0.950 | 0.977 | **+0.026** |
| **集成 r18+mnv3** | 12.72M | 51 MB | 0.8526 | — | 0.0% | 0.962 | 0.989 | +0.028 |
| **集成 r18+effnet_b0+mnv3** | 16.77M | 67 MB | **0.8706** | — | 0.0% | 0.945 | 0.979 | +0.034 |

> 三处口径说明，避免误读：
> · **参数量/体积按实际 `.pt` 实测**（`sum(v.numel())` 与文件字节），
>   与早期文档里按名字估的 5.3M/2.5M 不同 —— 后者偏大。
> · **"折间波动"有两种算法**：`--select best` 各折日志里打印的是
>   "各折最优轮次 AUC"的标准差（那是最优值的散布，会随选择次数变化）；
>   `select=last` 那行用**交付 OOF 向量逐折复算的 std**，与同一行的 AUC 同源可比。
>   两者不是一回事，不要混着引用。
> · **`resnet18 @320px` 那一行已移除** —— 它是在 683 只旧训练集上做的，
>   数据集换成 776 只后无法同表比较。320 的结论单独保留：
>   在 683 只上它域内不差（0.8261）但跨模型分数平移达 **−0.475**，
>   照搬 0.5 阈值会拒掉一半好图 —— 这是"分辨率不是杠杆，校准才是"的证据。

**四个单模型的域内 AUC 落在 0.811~0.857**，彼此差距仍然和种子噪声同量级。
上一节那个"架构排序"是跑一次的幻觉 —— 第一轮 resnet34 看着最稳（0.8057）、
resnet18 次之（0.8156），换成固定种子 + 776 只之后两个数变成了 0.8261 / 0.8387，
排序直接变了。**不要用单次 OOF AUC 在几个架构之间挑。**

**真正稳定带来提升的是两件事：加数据、做集成。**
683 → 776 → 862 只（两次都只补 good），单模型维持在 0.83~0.86，
集成把交付模型抬到 **0.8664**。

> 加真实出图那 86 只之后域内 AUC 几乎没动（0.8678 → 0.8664），
> **但真实分布上的表现是质变** —— 见第十七节 17.6。
排序本身就不稳定。所以**不要**根据单次 OOF AUC 在几个架构之间挑。

集成再从单模型最好的 0.8531 抬到 **0.8678（r18+b0）/ 0.8739（三路）**。

### 12.2b ★ 修正：跨模型误报率必须在"阈值对齐"后比较

**之前写在这里的结论是错的，这里撤回。**

第一轮我按**固定 0.5 阈值**比较跨模型误报率，得到
"resnet34 把 84% 的好手判成坏手，它背下了 IL 画风指纹"，
还把它当成最有价值的发现写进了文档。

固定种子重跑后，resnet34 的跨模型误报率变成了 **0.0%**。同一份数据、
同一份代码，结论翻转 —— 说明那个 84% 不是"认画风"，而是**校准崩塌**：

```
resnet34 第一轮：域内好手中位 0.944，跨模型好手中位 0.244   → 整体塌到阈值下方 → 全部误报
resnet34 第二轮：域内好手中位 0.944，跨模型好手中位 1.000   → 没有塌   → 零误报
```

> 第一轮那组数字**已经无法从盘上复算**（OOF 向量被第二轮覆盖），
> 只能引用当时日志里记下的值。第二轮的两个 0.944 / 1.000 可复算。

**固定阈值下的误报率把"判别力"和"校准"混在了一起。**
域外分数整体平移多少，取决于这一轮训练恰好收敛到哪里，波动极大。
拿它跨架构比较，比的是运气。

正确做法是**先按域内工作点对齐阈值**：把每个模型的阈值调到
"让域内 15% 的好手被拒收"，再看它在没见过的画风上拒收多少。
这样判别力与校准被分开，架构之间才可比：

| 架构 | 对齐阈值 | 域内抓出坏手 | 跨模型误报 | 相对域内 |
|---|---|---|---|---|
| resnet18 | 0.424 | 58.6% | 0.0% | 0.0× |
| efficientnet_b0 | 0.497 | 65.6% | 2.7% | 0.2× |
| mobilenet_v3_small | 0.590 | 60.8% | 1.3% | 0.1× |
| resnet34 | 0.316 | 60.8% | 25.3% | 1.7× |
| **集成 r18+effnet_b0（交付）** | 0.547 | **71.0%** | **0.0%** | 0.0× |
| **集成 r18+mnv3** | 0.531 | 70.4% | 0.0% | 0.0× |
| **集成 r18+effnet_b0+mnv3** | 0.560 | **72.6%** | 0.0% | 0.0× |

**修正后的结论**：阈值对齐之后，**所有架构的跨模型表现都不差于域内**
（最高也只有 1.2 倍）。也就是说，在这个**受控实验**里，
没有任何一个架构真的"背下了画风"。

> ⚠ **但这个结论有边界，第十七节把它推翻了**：这个实验只换了模型族，
> 画风/背景/构图/画面占比都锁死成我自己的模板。
> 换到**真实出图**上，分数平移是 −0.258，照搬阈值误报 29.8%。
> 所以准确的读法是："**只换模型族**时阈值可迁移"，不是"能直接用于实际出图"。

### 12.2c 真正的跨模型风险：阈值不可迁移

看"分数平移"那一列（跨模型好手中位分 − 域内好手中位分）：

| 架构 | 平移 | 含义 |
|---|---|---|
| **集成 r18+effnet_b0** | **+0.026** | 换模型族后分数几乎不动，阈值可以直接沿用 |
| 集成 r18+effnet_b0+mnv3 | +0.034 | 同上 |
| efficientnet_b0 | +0.002 | 同上 |
| resnet18 | +0.018 | 同上 |
| resnet34 | −0.010 | 同上（但固定阈值误报 25.3%，校准偏差） |
| （参考，683 只旧集）resnet18 @320px | **−0.475** | **必须**重新标定，否则一半好图被误拒 |

> ⚠ 这一列测的是**跨模型族**（同模板换模型），不是真实域偏移。
> 真实出图上的平移在补数据前是 −0.258，补完降到 +0.008 —— 见 17.6。

这才是"换模型会不会崩"的真实答案：
**不是判别力失效，而是分数整体漂移，导致固定阈值失效。**

补完 good 样本之后，这件事明显好转：交付的那个集成平移只有 **−0.003**，
意味着**换模型族后阈值可以直接沿用**；而旧 683 集上的 resnet18@320
平移是 −0.475，照搬 0.5 阈值会拒掉一半好图。
同一套训练流程，平移量从 −0.475 到 +0.060 差了两个数量级 ——
**说明"分数平移"这个指标本身对数据量和架构都很敏感，
不能靠一次实验就给某个架构定性。**

所以选型的正确标准是"域内 AUC 高 **且** 分数平移小"，
两者都满足的是 **r18+effnet_b0 集成**（0.8664 / 跨模型族平移 +0.026 /
真实分布平移 +0.008）。

### 12.3 跨模型测试集为什么没有坏手可测

原本的计划是算一个"跨模型 AUC"。但用 FLUX.2 生成的 75 只手**全部是 good**
（0 个 bad）。Krea2 也做了抽样，同样基本不出错手。
这正好印证了用户说的那句：

> 老模型（SD/XL/IL/Pony）经常画错手；新模型（FLUX/Qwen/Krea2/Anima）经常画对。

没有坏样本，AUC 就算不出来。所以这里换了指标：
**误报率 —— 模型在没见过的画风上，把好手判成坏手的比例。**
对"筛废图"这个用途来说，这恰恰是最该关心的数字
（一个只认 IL 画风的模型，换个模型就会疯狂误报）。

### 12.4 集成（推荐默认）

两个"各自独立犯错"的模型平均一下，域内涨、跨模型不变：

| 组合 | 域内 OOF AUC（排名平均¹） | 域内 OOF AUC（概率平均，可部署） | 跨模型误报@0.5 | 分数平移 |
|---|---|---|---|---|
| resnet18 + mobilenet_v3_small | 0.8529 | 0.8526 | 0.0% | +0.011 |
| **resnet18 + efficientnet_b0（交付）** | 0.8705 | **0.8664** | **0.0%** | **+0.026** |
| resnet18 + mobilenet_v3_small + efficientnet_b0 | **0.8727** | **0.8706** | 0.0% | +0.034 |

¹ 排名平均按 `_ensemble.py` 的写法（`rankdata(v)/len(v)` 归一化后取均值）。
**部署结论一律以概率平均为准。**

用**概率平均**而不是排名平均：排名平均的域内数字更好，
但单张图没有"同批其它样本"可排，部署时算不出来。

最终交付物 = `resnet18 + efficientnet_b0` 概率平均集成，**共 61 MB**，
域内 OOF AUC **0.8664**，阈值对齐后跨模型误报 **0.0%**，
**真实出图上误报 2.1%**（补数据前是 29.8%，见 17.6）。

三路集成能到 0.8706、域内召回 72.6%，体积 67 MB、真实分布平移 +0.034。
差距只有 0.004 AUC，**默认仍用两路**；要极致召回就改一条 `ENSEMBLE` 常量。
`resnet18+mnv3` 那一组是"体积最敏感"时的选择（0.8526 / 51 MB）。

### 12.5 与 CLIP 基线的对比

**同一份 776 只训练集**（`_baseline6.py` 已改为可传列表路径，
日志 `_baseline776_clip.log`）：

| 方案 | 体积 | 域内 OOF AUC | 手势内平均 | IL 子集 | Anima 子集 |
|---|---|---|---|---|---|
| CLIP ViT-H/14 线性探测 | 2411 MB + 1281 参数 | 0.7709 | 0.7291 | 0.705 | 0.880 |
| CLIP ViT-H/14 微调 | 2411 MB | 0.7957 | 0.7410 | 0.715 | 0.927 |
| **自有小模型集成（resnet18+effnet_b0）** | **61 MB** | **0.8678** | **≈0.82** | 0.877 | 0.942 |

同数据、同折数（都是 5 折）下，**小模型比最好的 CLIP 高 0.072 AUC，
体积只有 1/40**。这是这一轮最干净的一组对比。

一个值得注意的细节：CLIP 在两个模型子集上差了 0.21
（IL 0.705 vs Anima 0.927），说明 CLIP 特征里"画风"的权重远大于"手部结构"。
小模型在同样两个子集上是 0.877 / 0.942（差 0.065），
差距明显更小 —— 它更依赖手本身，而不是整体画风。

CLIP 线性探测随数据量变化的方向**顺手记一下，免得误读**。
**同一套线性探测流程**在四个数据集版本上：

| 数据版本 | 脚本 / 日志 | 线性探测 OOF AUC |
|---|---|---|
| 279 只 | `_baseline5_finetune.py`（`_finetune5.log`） | 0.8229 |
| 336 只 | `_baseline6.py`（`_baseline6.log`） | 0.7453 |
| 683 只 | `_baseline6.py`（`_baseline7_clip.log`） | 0.7719 |
| **776 只** | `_baseline6.py`（`_baseline776_clip.log`） | **0.7709** |

这四个数不能串成一条"数据越多越好/越差"的曲线 —— 它们来自四个不同的
数据集版本，手势构成也不同。（另外 0.8229 那个数**只在日志里**，
`_baseline5\oof.npz` 存的是同一次微调的 OOF 0.8085，
线性探测的分数向量当时没落盘，所以它无法从工件复算。）

真正说明问题的是另一个对比：在**同一份 683 只**上，
CLIP 微调 0.7665 与线性探测 0.7719 几乎一样（差 0.0054），
说明冻结的 CLIP 特征里已经没有更多可利用的手部结构信息了；
而自训小模型能拿到 **0.8678** —— 高出的部分来自"被迫只看手"，
不是来自更大的底座。

另外一个细节：CLIP 在 IL 上只有 0.684、在 Anima 上有 0.886，
两者差了 0.2 —— 说明 CLIP 特征里"画风"的权重远大于"手部结构"。

注意 CLIP 这条线的对比也**不是完全干净**：线性探测用 5 折，
微调用的是 3 折（`_baseline6.py:188`），两者折数不一致。
不过 0.0054 的差距远小于折数差异能造成的量级，不影响上面那句结论。

### 12.6 工作点（阈值怎么选）

AUC 只说明排序能力，实际筛图要选阈值。以 r18+effnet_b0 集成为例：

| 阈值 | 域内抓出坏手（召回） | 域内误报率 | 真实出图误报 |
|---|---|---|---|
| 0.30 | 50.5% | 7.2% | 0.0% |
| 0.40 | 59.1% | 9.5% | 0.0% |
| 0.50 | 68.3% | 12.7% | 0.0% |
| **0.547**（按域内 15% 误报对齐） | **71.0%** | 15.0% | **2.1%** |
| 0.60 | 74.2% | 17.8% | — |
| 0.70 | 80.6% | 24.0% | 8.5% |

注意两件事：

1. **准确率在本任务上没有参考价值**：好样本占 73%，
   "全部判成好"就能拿到 0.728 的准确率。要看的是 AUC 与召回/误报的权衡。
2. **不要跨架构套用同一个 0.5**。第七节 12.2c 已经说明，
   不同架构在域外的分数平移量从 +0.016 到 −0.475 不等，
   照搬一个阈值等于把校准问题当成判别问题。
   换模型族之后**必须用自己的数据重新标一次阈值**。

### 12.7 分手势 AUC（r18+effnet_b0 集成）

| 手势 | n (good/bad) | AUC |
|---|---|---|
| own hands together | 81 (55/26) | **0.923** |
| open hand, spread fingers | 130 (61/69) | 0.849 |
| hand on own chest | 72 (58/14) | 0.836 |
| outstretched hand | 82 (59/23) | 0.797 |
| v sign | 56 (51/5) | 0.796 |
| peace sign | 92 (80/12) | 0.785 |
| pointing | 66 (52/14) | 0.780 |
| holding object | 67 (60/7) | 0.748 |
| thumbs up | 71 (59/12) | 0.727 |
| clenched hand | 59 (55/4) | 0.682 |

> **别把这行读成"坏样本越多 AUC 越高"。** 独立复核算过：
> 坏样本数与 AUC 的 Spearman 相关只有 **0.150（p=0.68）**，不成立。
> `peace sign` 12 个坏样本拿到 0.835，而 `pointing` 14 个只有 0.716；
> `v sign` 只有 5 个坏样本却排在上面。
> 正确的说法是：这些手势的 AUC **置信区间都很宽**（每折只剩 1~2 个坏样本），
> 表里的排序和数值大部分是噪声，逐项解读没有意义。
> 换一次种子重跑，排序会明显变化 —— 这正是 12.2 要说明的事。

手势之间数值的跨度是 0.682 ~ 0.923，但如上所述，这个跨度不可当作难度排序。
值得注意的是 `clenched hand` 补了 good 之后（33→55）AUC 反而从 0.758 掉到 0.609 ——
**不是变差，是分母变了**：只有 4 个坏样本时，AUC 基本由这 4 个样本的排序决定，
多一点或少一点好样本就能让它大幅摆动。这正是"bad 不足"的直接后果。

### 12.8 结论

1. **能做出来，而且不需要 CLIP。** 61 MB 的自训小模型集成，
   域内 AUC **0.8664**，超过 2.4 GB 的 CLIP 线性探测（0.7709，同数据）。
2. **"只换模型族"测不出真实域偏移；但补真实数据能修好它。**
   受控实验（同模板只换模型族）平移 +0.026，看着没问题；
   而真实出图上原来是 **−0.258、误报 29.8%**（17.3）。
   把 86 只真实出图裁的手加进训练后，真实分布平移降到 **+0.008、误报 2.1%**，
   域内 AUC 几乎没损失（17.6）。**这才是正确的修法。**
3. **坏样本不是"没抽到"，是"不存在"。** 七种配方逐一试过（第十五节），
   共 49 个新样本 **bad = 0**：IL 在能找到的任何设置下都不怎么把手画错。
   唯一"高产"的旧 `only hands` 配方（旧集 58.9%、复刻 pilot 25%）
   产出的其实**主要是废裁剪**（一条光滑手臂、看不出手形），
   不是结构性错误 —— 那一批在第十五节的标准下应判 skip。
   所以缺的不是算力，是数据本身；要补只能靠用户实际遇到的废图（主动学习）。
4. **最大的天花板不是模型，是标签 —— 而且比想象的严重。**
   三级盲测（第十六节）给出量化：我标 bad 的样本里只有 **2%**
   能被独立复现为客观结构错误，**81% 被判 fine**，干净子集上 **kappa = −0.003**。
   所以 **0.8678 这个 AUC 度量的是"复现我的判定边界"，不是"检出画错的手"**。
   这一条比上面三条加起来都重要。

## 十三、★ 独立盲测：标签才是天花板

### 13.1 为什么要做

前十二节所有数字都有一个共同的前提：**训练标签和评估基准是同一个人标的**
（我自己，逐格看图）。如果我的判定有系统偏差，AUC 再高也只是
"模型成功复现了我的偏见"，而不是"模型看懂了手"。

所以做了一次盲测：把 48 只手交给一个**独立评估者**，
只给图和一份写死的判定标准，**不给标签、不给模型分数、不给手势**。
材料由 `_blind_prep.py` 生成（拼图里只有编号），结果比对见 `_blind_compare.py`。

### 13.2 结果

抽样是分层的：32 只我标 good + 16 只我标 bad。

| | 独立评估者 |
|---|---|
| **我的判定** | good 42 / bad 1 / skip 5 |

双方都给出 good/bad 的 43 格里：

```
一致 32/43 = 74.4%      但 Cohen's kappa 只有 0.116
```

一致率看着还行，**kappa 却接近随机** —— 因为评估者几乎全判 good（42:1），
期望偶然一致率 pₑ 就高达 0.711，光靠"都猜多数类"就能拿到接近这个数的一致率。
真正的信息在混淆矩阵里：

| 行=我 / 列=它 | 它 good | 它 bad |
|---|---|---|
| **我 good** | 31 | 0 |
| **我 bad** | **11** | 1 |

**关键数字：我标 bad 的 12 格里，独立评估者只同意了 1 格（8%）。**
另外我标 bad 的 4 格被它判成 skip（糊到没有手形，它按标准的 skip 条款处理），
累计我 16 个 bad 里有 15 个没有被独立复现。
反过来我标 good 的 31 格，它**全部同意**。

分歧完全不对称：**good 一致率 100%，bad 一致率 8%。**
矛盾全部集中在"什么叫画错了"这个定义上。

### 13.3 这意味着什么

1. **报告里的 AUC 度量的是"复现我的判定"，不是"检测客观的手部错误"。**
   这句话应该写在任何引用这些数字的地方。
2. **"坏手"这个类别里，很大一部分是主观的。**
   客观可查的（多指、融合、关节不可能）很少见；
   大量样本其实落在"结构糊、不可信、看着别扭"这种灰区。
3. **灰区的判定受画风干扰**：评估者反复在报告里说，
   "风格化的长手指只要有指节和指甲就算 good" ——
   而我倾向把"糊成一团"直接判坏。这是两种都说得通的取向，
   但它们混在同一个标签列里，模型学到的就是一个漂移的边界。
4. **对"筛废图"这个用途来说，这未必是坏事。**
   "看起来糊、不可信"本来就是合理的拒收理由，
   所以这个模型作为**个人化的筛图器**是可用的。
   但它不能当成一个客观的"手部正确性检测器"来用或来引用。

### 13.4 怎么解决

不是模型问题，也不是继续扩数据能解决的。只有两条路：

1. **多标注者 + 共识标签**：同一批图至少两个人独立标，
   只保留双方一致的作为基准，不一致的判为"灰区"单独处理。
   `_blind_prep.py` + `_blind_compare.py` 就是为此准备的工具。
2. **重新定义标签，只留可客观核验的**：明确限定为
   "手指数量错 / 手指融合 / 出现两个指甲 / 关节方向不可能"，
   把"糊""不可信"移出 bad。代价是坏样本会大幅减少
   （从盲测的比例推断大概只剩三到四成），但剩下的每一个都站得住。

**建议先做第 2 条**：门槛低、立刻能执行，而且它会让下一轮的 AUC 更可信 ——
即使数字会变低。

## 十四、独立审计与可复现性

用户建议引入独立第三方评估，于是做了一轮审计：
让一个不知道我结论的 agent 只读盘上的工件，重新推导 17 条声明。
完整报告在 `_audit_report.md`。它抓出了三个真问题，都已修复：

### 14.1 抓出的问题

1. **陈旧工件（严重）**
   为了补一个 ONNX 导出，我重跑了 resnet18。这次重跑**沿用了同名文件**，
   于是覆盖了旧的那份 OOF 向量，而基于旧向量写好的集成结论
   （0.8412 / 1.3%）就再也无法从盘上复现了。
   → 修复：文件名带 `size` 与 `select` 后缀（`_train_small.py`），
   同名覆盖不可能再发生。

2. **训练不可复现（严重，根因）**
   数据增强用的是全局 `numpy.random`，**从没设过种子**。
   同一份数据、同一份代码，两次跑的 OOF AUC 差到 0.01 以上，
   跨模型误报率甚至从 84% 翻到 0%。
   → 修复：`--seed`（默认 42）同时固定 numpy / torch / cuda 三处种子，
   并把 `seed`、`select`、`fold` 一并写进 npz。
   **12.2 的整张表因此重跑过。**

3. **checkpoint 选择偏差（中）**
   每一折都是"用该折自己的验证 AUC 挑最优轮，再拿它算 OOF"，
   这条 AUC 因此带乐观偏差；折间"波动"统计的也是最优值的散布，
   不是训练本身的稳定性。
   → 修复：新增 `--select last`（固定轮数跑到最后，不做选择）。
   实测偏差在 683 只上是 **0.0019**（0.8040 → 0.8021），
   但在 776 只上变成 **0.0257**（0.8387 → 0.8130）——
   一次实验量到的结论不能推广（这本身就是审计那条意见的教训）。
   结论应该是：**这个偏差量级在 0.002~0.026 之间，取决于数据量与早停行为，
   不可忽略，所以 12.2 表里把它单独列成一行。**

### 14.2 审计确认无误的部分

- ~~训练集 683 行、497 good / 186 bad~~ → 审计当时是 683 行；
  之后补了自然批，现在是 **776 行、590 good / 186 bad**（见 12.1）
- `efficientnet_b0` 0.8215、`mobilenet_v3_small` 0.7859、`resnet34` 0.8057 ✓
  —— 这三个是**第一轮未固定种子、683 只**的值；12.2 表已换成
  固定种子 + 776 只的重跑值（0.8493 / 0.8531 / 0.8261）。
  三批数字都真实存在，分别属于三次不同的训练，不要混着引用。
- 跨模型误报率四架构**（第一轮）**全部精确复现 ✓
  —— `cross_pred_*.json` 此后又被覆盖过两次（固定种子 683 只、再补数据到 776 只），
  现在盘上的值是 0.0 / 13.3 / 5.3 / 0.0%，对应 12.2 表。
- **防泄漏：训练集与跨模型测试集的 `hand_id` 交集为 0** ✓
  （路径交集也是 0）
- 训练集内无重复 `hand_id`、无重复路径、无同路径冲突标签 ✓
- 四个 npz 的 `y` 两两一致且等于训练集派生向量（行序一致）✓
- CLIP 两个基线 0.7719 / 0.7665 逐字存在于日志，并已独立复算 ✓

### 14.3 审计指出但我保留的取舍

- **跨模型集没有负样本**：只能测单侧误报率。
  一个恒输出 0.99 的模型能拿到"完美"的 0% 误报率却什么都没检测。
  → 因此 12.2b 里**必须与"域内抓出坏手"一列并读**，单独看误报率会选错模型。
- **`Anima|clenched hand` 只有 1 个样本**，成为分层键里的单样本层，
  sklearn 每次都会警告 `n_splits=5` 不满足。日志里被 PowerShell 的
  stderr 噪声埋住了。这是数据问题，留待补样本。
- **`cross_records.json` 77 条 vs `cross_test.json` 75 条**：
  差的两条是我判为 skip 的（一条裁到了领结、一条糊到看不清），
  属正常丢弃，已在 labels.json 里记录。

### 14.4 端到端一致性

审计无法验证"上线的 `.pt` 前向能否复现存下来的分数"，补测了：
用 `_predict.py` 对跨模型集**全部 75 张**逐张推理（batch=1），
与训练时存入 `cross_pred_*.json` 的集成分数比对 ——
**最大绝对差 0.000983，均值 1.2e-4，3/75 超过 5e-4，0/75 超过 1e-3。**

差值不是零，来源是批大小不同带来的浮点累加顺序差异（训练时 batch=32，
推理时 batch=1），不是预处理不一致 —— 因为如果有预处理差异，
差异会是系统性的，而实测相差 1e-4 量级且符号随机。
结论"推理侧与训练侧对齐"成立，但**"逐位一致"是说过头了**。

## 十五、为什么"每个手势 bad ≥50"这个目标做不到

### 15.1 目标与缺口

初始目标是**每个手势 good/bad 各 50+，总量约 1000 只**，
理由是坏样本太少时每折验证里只剩 1~2 个，AUC 完全由噪声决定。

当前 **862 只**（good 676 / bad 186，其中 86 只来自真实出图、手势记为 unknown）。
**good 侧已经达标**（10 个手势全部 ≥50），bad 侧只剩 `open hand` 过了 50：

| 手势 | good | bad | bad 距 50 还差 |
|---|---|---|---|
| clenched hand | 55 ✓ | 4 | 46 |
| v sign | 51 ✓ | 5 | 45 |
| holding object | 60 ✓ | 7 | 43 |
| peace sign | 80 ✓ | 12 | 38 |
| thumbs up | 59 ✓ | 12 | 38 |
| pointing | 52 ✓ | 14 | 36 |
| hand on own chest | 58 ✓ | 14 | 36 |
| outstretched hand | 59 ✓ | 23 | 27 |
| own hands together | 55 ✓ | 26 | 24 |
| open hand, spread fingers | 61 ✓ | 69 ✓ | — |
| **合计** | **676** | **186** | **333** |

（good 那一列是这一轮补出来的：原先有 6 个手势低于 50，
用 N1 配方定向补了 96 只 good 之后全部达标 —— 补 good 是可行的，
补 bad 不可行，差别就在下面这一节。）

### 15.2 七种配方逐一试过，没有一种能产出结构性错手

如果"坏手"是模型画出来的，那换个更容易翻车的配方就能刷出来。
于是把可能压制/诱发错误的杠杆**逐个试了一遍**（每格都是手部特写级别的可判样本）：

| 配方 | 内容 | 样本 | bad | skip |
|---|---|---|---|---|
| `_expand_gen` | quality + `hand focus` + 手势 | 287 | 3（1.0%） | 25 |
| `_hard_gen` | 同上 + 多手交叠/极限透视 | 60 | 5（8.3%） | 0 |
| **N1** | 去掉 `hand focus`，保留主体 | 6 | 0 | 1 |
| **N2** | 连主体也去掉，只留手势 tag | 6 | 0 | 0 |
| **N3** | 再去掉 quality 词 | 5 | 0 | 0 |
| **N4** | 主体改成 cowboy shot（手更小更远） | 5 | 0 | 0 |
| **N5** | 步数降到 8、cfg 6（来不及收敛） | 8 | 0 | 0 |
| **N6** | 步数降到 11 | 8 | 0 | 0 |
| **N7** | 复刻旧 `only hands` 配方 + 手势 tag | 11 | **0** | **5（45%）** |
| **R1/R2** | `IL_Concept_Contortion_V1` LoRA，强度 1.0 / 1.6（扭曲姿势） | 8 | 0 | 1 |
| **R3** | 采样器换 `euler_ancestral` + `normal` | 6 | 0 | 1 |
| **R4** | 采样器换 `dpmpp_2m_sde` + `karras` | 5 | 0 | 4 |

**两轮下来一共 11 种配方、68 个新样本，bad = 0。**

> 这批里有 13 只判为 good（clenched hand），**没有并进训练集** ——
> 第十二节的数字是绑定在 776 只这一版数据集上的，
> 每加一次数据就得整套重训重算（40 分钟）才能保持自洽。
> 样本和记录留在 `_lora/hands/`、`_lora/lora_records.json`，
> 要扩数据时可以直接用，只是那样 12.2 的整张表都要重跑。

R4 那 4 个 skip 要单独说明：`dpmpp_2m_sde` + `karras` 这个组合配这个模型
直接出**整张废图**（红/青抽象色块，根本不是插画），不是"手画错了"。
这类样本必须丢弃 —— 把它标成 bad 就又把"画质/生成失败"混进了手部结构标签，
正是第 15.3 节说的那个坑。

连"把步数砍到 8 步"这种最粗暴的手段都没用 —— 出来的手只是**画得软、渲得糊**，
结构（指数量、指节、指甲、关节方向）依然成立。
那是"画质差"，不是"画错"，两者不能混进同一个标签列。

### 15.3 ★ 那旧的 58.9% 是怎么来的

唯一的"高产"记录是**最早那批旧 IL：136/231 = 58.9% bad**。
但它已经被同一套标准否掉了 —— 盲测（第十三节）显示我那批 bad 判定
**独立复现率只有 8%**。

N7 这一列给出了机制上的解释：它复刻的正是旧配方，
产出率上确实"更糟"，但糟糕的方式不是"手画错"，
而是**裁出来的根本不像一只手** —— 45% 的样本是
"一条光滑的手臂／一块糊掉的肤色，看不出手形"。

旧那 136 个 bad 里，很大一部分应该就是这类样本：
在我早期的严标准下被判 bad，在这一轮标准下应该判 **skip**。
换句话说：

> **旧集 59% 的"坏"，主要不是模型把手画错了，
> 而是裁剪质量控制失败 + 我早期判定偏严的叠加。**

这也正好解释了盲测的 kappa 只有 0.116 —— 不是随机噪声，
而是**同一个词（bad）在两个阶段指的不是同一件事**。

### 15.4 结论：这个目标在物理上不可达

要把 333 个缺口补齐：

- 按最乐观的 25% 产出率（来自 n=12 的小样本，95% 置信区间约 5%~57%，
  基本不构成证据）也要生成 **1330 张**，再**人工判读约 1400 只手**（≈120 个标注批次）。
- 而真正可归因到手势的配方（N1~N6）产出率实测是 **0%**。
- 唯一有产出记录的配方（N7 / 旧配方）产出的**不是坏手而是废裁剪**，
  既补不到"结构性错误"这一类，也不能用来按手势评估。

所以缺的不是算力也不是时间，**是数据本身不存在**：
`rinAnimeBlendArblend_v20` 在我能找到的任何设置下，
都不怎么把手的结构画错。

**正确的应对不是继续刷数据，而是把目标改成可达且有意义的形式：**

1. **承认并保留现状**：776 只（good 590 / bad 186）。弱手势的 AUC 置信区间宽这件事
   写进结论，而不是靠注水样本掩盖。
2. **补 bad 只能靠真实分布**：从用户实际遇到的废图里收（主动学习），
   因为"什么算废"本来就依赖使用场景，合成数据造不出用户眼里的废。
3. **先修标签定义**：把"糊、不可信、裁剪废"从 bad 里拆出去单独成一类
   （或直接 skip），只留可客观核验的结构性错误。
   这一步做完，同样的数据量下 AUC 会下降，但那个数字才是可信的。

这一节是**负面结果**，但它把一条走不通的路彻底封死了 ——
省掉的是"再生成几千张、再标几千张、然后发现 AUC 没变"的那几天。

## 十六、★★ 三级盲测：坏标签本身几乎不存在

第十三节的二分盲测给出 kappa 0.116，但二分法有个说不清的地方：
"糊、不可信、看着别扭"这类灰区没地方放 —— 我早期塞进 bad，
评估者塞进 good，两边都不算错。所以这一轮改成**三级判定**重做。

### 16.1 设计

- 从 776 只训练集里**分层抽 96 只**：我标 good 的 48 只 + 我标 bad 的 48 只。
- 交给一个**不知道我标签**的独立评估者，只给图和标准，不给手势、不给模型分。
- 标准是三级的，而且**要求判 wrong 必须报出编号理由**（1 指数量不对 /
  2 手指融合 / 3 比例不可能 / 4 整只手没有结构 / 5 关节方向不可能），
  说不出编号就只能判 fine 或 questionable。
- 材料由 `_blind2_prep.py` 生成，比对见 `_blind2_compare.py`。

### 16.2 结果

评估者对 96 格的判定：**fine 73 / questionable 21 / wrong 2**。

和我标签的交叉表：

| | 它 fine | 它 questionable | 它 wrong |
|---|---|---|---|
| **我 good（48）** | 34（71%） | 13（27%） | 1（2%） |
| **我 bad（48）** | **39（81%）** | 8（17%） | **1（2%）** |

**我标 bad 的 48 格里，只有 1 格（2%）能被独立复现为"客观画错"。**
81% 被判为 fine —— 用的是我自己写的标准。

去掉灰区之后的**干净子集** 75 格：**73 fine / 2 wrong**。
两套标注在干净子集上的 **kappa = −0.003** —— 等于零一致，
也就是说我的 good/bad 划分里，**没有任何独立评估者能复现的信息**。

两个被判 wrong 的：
- `#05` 我标 **good**，它判 wrong（条款 3：两根手指是等宽平板、无指节无指甲）——
  **这是我漏掉的真实错误。**
- `#51` 我标 bad，它判 wrong（条款 1：数出 6~7 根指头）—— 这一格对上了。

### 16.3 灰区里是什么

评估者把 21 格打成灰区，并归成三类，这个归类很有说服力：

1. **数量根本无法核验的姿势** —— 双手交扣/指尖相抵，能看见指甲，
   但追不清某根手指属于哪只手。**指数量这类错误在这种姿势下本身不可判定。**
2. **极端特写/裁剪过紧** —— 掌指交界糊成一团。
3. **平滑到没有任何结构标记** —— 指节和指甲都消失了，只剩分缝。
   有一格它说"指端是球状肉垫，像脚趾"。

它自己也说明了口径：**只要还能看到指甲或指节横纹，就判 fine**，
只有"既无指节又无指甲、且比例离谱"才判 wrong。
所以它的 wrong 只有 2 个是**偏保守**的结果 ——
但那 21 个灰区里相当一部分按更严的口径也会落到 wrong。
换句话说：**"画错"这件事的真实密度在 2%~25% 之间，取决于口径有多严。**

### 16.4 这意味着什么（本节是全项目最重要的结论）

1. **不是"坏样本还没收集够"，是"坏样本这个类别本身很稀薄"。**
   在 96 个真实样本里，客观可核验的结构错误只有 2 个量级。
   要让**每个手势**都凑到 50 个客观 bad，按 2% 的密度需要
   **每个手势约 2500 张**、总计约 2.5 万张并逐张人工判读 —— 不现实；
   即使按最宽松的 25% 口径，也要约 2000 张。第十五节已经证明生成端补不出来，
   这一节进一步说明就算补得出来，密度也不够。
2. **模型那个 0.8829 的 AUC 到底在度量什么，现在很清楚了。**
   同一批干净子集上：以**我的标注**为基准算，AUC 0.8829；
   以**独立判定**为基准算，0.8082（而且只有 2 个负样本，基本没有统计意义）。
   差别就在这 —— 模型学得非常好的是**我的判定边界**，
   不是"手有没有画错"。我此前在 13.3 就提醒过这一点，这里给出了量化：
   **81% 的 my-bad 在被独立复核时其实是 fine。**
3. **这解释了前面所有的反常现象**：
   - 为什么 11 种配方都产不出坏手 → 因为模型画手的水平本来就够；
   - 为什么旧集 59% 的"坏"无法复现 → 因为那是我早期更严的口径，不是客观错误；
   - 为什么二分盲测 kappa 只有 0.116 → 因为灰区被硬塞进了二分类。
4. **对"筛废图"这个用途，结论要改写。**
   一个依赖"我的手部判定"的模型，本质是**个人化偏好过滤器**，不是正确性检测器。
   它有用 —— "看着糊、不可信"确实是合理的拒收理由 ——
   但**不能对外宣称"它能检出画错的手"**，因为按客观标准，
   这类图在新模型出图里本来就很少见。

### 16.5 建议的下一步（按性价比排序）

1. **先问清楚要筛什么**。如果目标是"筛掉我看着别扭的图"，现有模型可用，
   但要用**你自己的**一批图重标阈值（13.4 的 `_blind_prep.py` + `_blind_compare.py` 就是工具）。
   如果目标是"检出客观画错的手"，那么这个任务在当代模型上**价值密度太低**，
   不如把精力放在崩坏检测的其它维度（整体构图、肢体比例、文字、多手）。
2. **真要继续做手部，只能走客观口径**：只用 1/2/5 三条（数量、融合、关节方向），
   把"糊""没结构"整体移出 bad。数据量会掉到十分之一，但每一个都站得住。
3. **多标注者共识**是唯一能把这件事做扎实的办法。单人标注（无论是我还是一个 subagent）
   在 kappa≈0 的情况下，做什么模型都是在拟合噪声。

> 本节的价值是**否定性的**：它把"再多标几千张就能解决"这条路的尽头提前标了出来，
> 省掉的是一周时间和几万张图。

## 十七、★★ 真实使用分布测试：跨模型"没事"是个假象

### 17.1 之前漏掉了什么

第十二节算出跨模型分数平移 **−0.003**，看起来"换模型族后阈值直接可用"。
但那批测试集是这么造的：用 FLUX.2 跑**我的同一个模板**
（`anime illustration, 1girl, solo, upper body, close-up on the hand, white background`），
只把"模型族"这一个变量换掉。

问题在于：**真实使用里变的从来不只模型族。** 画风、背景、构图、
手的画面占比、甚至是不是写实，全都在变。所以我那个实验
**控错了变量** —— 它证明的是"换模型、但仍是动漫风白底手部特写时，
阈值可迁移"，而不是"实际用起来能直接用"。

### 17.2 真实分布测试怎么做

从 ComfyUI 的 output 目录里，把**用户自己出的图**抽出来做测试集
（`_realuser_harvest.py`）：

- 排除我自己为数据集生成的目录（HandDataset / NaturalDataset / HardDataset /
  HandCross / LegacyDataset / LoraDataset）
- 剩下 **1466 张真实出图，分布在 113 个目录**，跨 Anima / IL / FLUX / Krea2 /
  AISPACE / 写实，时间跨度好几个月
- 按目录分层抽 72 张 → 检出 128 只手 → 人工标 60 只（47 good / 13 skip / **0 bad**）

**这批完全没参与训练**，而且不是我生成的，是最接近实际用途的一组数据。

### 17.3 结果：误报率接近三成

| | 训练域 | **真实使用分布** |
|---|---|---|
| 裁剪尺寸中位 | 450 px | **126 px** |
| 好手中位分 | 0.963 | **0.705** |
| 分数平移 | — | **−0.258** |

在训练域标定好的阈值（0.509，对应域内 15% 误报）上：

| 阈值 | 真实好手误报率（只看已标注的 47 只 good） |
|---|---|
| 0.253 | 10.6%（5/47） |
| 0.300 | 14.9%（7/47） |
| 0.365 | 19.1%（9/47） |
| 0.400 | 21.3%（10/47） |
| **0.509（训练域标定值）** | **29.8%（14/47）** |
| 0.700 | 46.8%（22/47） |

**照搬训练域阈值，每 10 张好图里要误判 3 张。** 这是日常使用会立刻感觉到的。

把阈值降到 **0.25 左右**，真实好手误报能压到 10% 上下 —— 代价是召回也会掉。
所以这不是"调个参数就完了"，而是要按用途权衡：宁可漏检就别调太低。

> 顺带说明 `_calibrate.py` 这个工具的口径差异：它是**无监督**的，
> 用你自己所有手部分数取分位数，因此会把"根本不像手"的废裁剪也纳入分布，
> 给出的阈值（10% 目标 → 0.365）比只按已确认好手算出来的
> （10% 目标 → 0.253）**偏高**。两者都有用：
> 前者不需要标注、立刻能用；后者要标 30~50 只但更准。

### 17.4 原因不是分辨率，是画风

第一反应是"真实裁剪只有 126px，太小了"。按尺寸分桶一看，**不成立**：

| 裁剪尺寸 | n | 好手中位分 | 低于 0.5 比例 |
|---|---|---|---|
| <100 px | 18 | 0.640 | 33% |
| 100–200 px | 16 | **0.916** | 25% |
| 200–400 px | 2 | 0.912 | 0% |
| >400 px | 11 | **0.696** | 36% |

分数**不随尺寸单调变化** —— 最小的那桶反而比 100–200px 差不了多少，
而 >400px 的大裁剪也有 36% 被压低。所以"放大一点就好了"是错的。

按来源目录拆开才看出真正的原因：

| 来源（用户某个日期/工作流） | n | 中位分 |
|---|---|---|
| 2026-07-26 | 6 | **0.961** |
| 2026-08-20 | 4 | 0.881 |
| 2026-07-29 | 4 | 0.769 |
| TextInjection | 5 | 0.648 |
| 2026-09-28 | 8 | **0.543** |
| 2026-07-27 | 4 | **0.062** |

**同一批真实数据里，不同画风的中位分从 0.06 到 0.96，差了一个数量级。**
模型不是"看不懂真实数据"，而是**只认训练时那两种画风（IL / Anima 的动漫厚涂）**。
写实风、线稿风、某些特定模型的画风，它一律打低分。

### 17.5 结论

1. **"跨模型泛化已解决"要改成"跨模型族的这个受控实验没发现问题"。**
   真实域偏移（画风 + 背景 + 画面占比 + 写实/线稿）远比单纯换模型严重。
   这是本项目里我**自己设计错的一个实验**，靠"用真实数据测一次"才暴露出来。
2. **这个模型现在不能直接拿去筛真实出图。** 用之前必须二选一：
   - **重新标定阈值**：在你自己的图上标 30~50 只，按目标误报率定阈值
     （0.3 对应约 15%）。`_predict.py` 的分数可以直接用，只是阈值要换。
   - **按画风分组标定**：如果某类画风（比如写实）你根本不用，
     就把它排除；如果用，就得分开定阈值。
3. **要真正修，得往训练集里加真实分布的样本**，
   而且**不能再用手部特写模板生成** —— 得用真实出图去裁手。
   这正好和第十六节的结论合起来：坏样本补不出来，
   但**好样本的分布**是可以也应该用真实数据纠正的。
4. 第 17.3 的 0 bad 再次印证第十六节：真实好手上，客观画错的比例依然接近 0。

> 这一节把"能用了"这个说法按下去了，但它给出的是**可执行的修正路径**：
> 换阈值（十分钟）→ 加真实分布训练数据（几小时）→ 才谈得上开箱即用。

### 17.6 ★ 修复：加 86 只真实出图裁的手，误报从 29.8% 掉到 2.1%

17.5 的第 3 条说"要真正修，得往训练集里加真实分布的样本"。这一节把它做了，
并且发现**需要的量比预想小得多**。

做法（`_realuser_harvest.py` 取 + 人工判）：

1. 从同一批真实出图里**再抽 110 张**，吸取 17.3 的教训，
   显式排除已被测试集用过的原图（脚本里做了断言，`_write_labels4.py` 里也有一条）。
2. 裁出 185 只手，人工判了 96 只：**86 good / 10 skip / 0 bad**。
3. 这 86 只作为 `user` 来源并入训练集，手势记为 `unknown`（真实出图没有手势标注）。
   训练集 776 → **862**（good 676 / bad 186），只多了 10% 的样本。

结果（其余一切不变，只重训）：

| | 补之前（776 只） | **补之后（862 只）** |
|---|---|---|
| 真实好手中位分 | 0.705 | **0.959** |
| 真实分布 vs 训练域 平移 | **−0.258** | **+0.008** |
| 真实好手误报 @0.509 | **29.8%**（14/47） | **2.1%**（1/47） |
| 真实好手误报 @0.5 | 29.8% | **0.0%** |
| 域内 OOF AUC | 0.8678 | **0.8664** |
| 跨模型（FLUX.2）误报 | 0.0% | 0.0% |

**代价几乎为零，收益是质变。** 域内 AUC 只掉了 0.0014（噪声级别），
而真实使用上的误报从"十张错三张"变成"约五十张错一张"。

### 17.7 这条修复带来的三条结论

1. **"数据不够"和"数据不代表目标分布"是两回事。**
   前面十五、十六节证明了**坏样本**补不出来（那是类别密度问题，真的没有）；
   但**好样本的分布**是可以补的，而且只要 86 只就能把最严重的缺陷修掉。
   这两件事以前被我混在一起谈，现在应该分开：
   - 坏侧：无解（客观密度约 2%）
   - 好侧：**只需按真实分布补一小批即可**
2. **训练域指标完全看不出这个问题。** 补数据前后域内 AUC 是 0.8678 / 0.8664，
   几乎一样；跨模型（FLUX.2）误报也都是 0%。**只有用真实出图测才看得到差别。**
   所以一个可交付的模型，测试集里**必须有真实分布的样本**，
   不能全用自己按模板生成的。
3. **`_calibrate.py` 依然是必要的兜底。** 2.1% 不等于 0，
   而且你换新模型、新 LoRA、新画风之后分布还会动。
   正确姿势是：先按自己的图跑一次 `_calibrate.py` 定阈值，再日常使用。

### 17.8 现在这个模型的实际状态

| 项目 | 结论 |
|---|---|
| 能不能脱离 CLIP 独立跑 | 能，61 MB + ONNX，零外部依赖 |
| 域内（IL/Anima 动漫风）能不能抓坏手 | 能，AUC 0.8664，15% 误报下抓出 71% |
| 换模型族会不会崩 | 不会（同模板受控实验 +0.026） |
| 真实出图上会不会乱报 | **补数据后误报 2.1%**，可用 |
| 能不能检出"客观画错的手" | **基本上没有这种样本可检**（第十六节，密度约 2%） |
| 该怎么用 | 当作**个人化偏好筛图器**：按自己的图定阈值，
只筛"我看着不对"的那一小撮；不要对外宣称"检出画错的手" |

## 十八、CivitAI 第三方取样：真正的瓶颈是检测器，不是质量模型

### 18.1 为什么要抓 CivitAI

前面所有测试集都出自我自己或用户的 ComfyUI —— 即便是"真实出图"那批，
也带着同一个人的提示词习惯。CivitAI 是货真价实的第三方：别人用
Pony / Illustrious / Anima / SDXL / FLUX / Krea2 甚至 DALL·E 出的图，
各种画风各种内容，我一个都没见过。

用公开 API `api/v1/images`（`nsfw=None`，只要全年龄）抓了两批：

| 批次 | 取法 | 张数 | 检出率 | 手部中位分 |
|---|---|---|---|---|
| A「当月最热」 | `sort=Most Reactions&period=Month` | 48（10 个模型族） | 98% | 0.770 |
| B「动漫族定向」 | 客户端按 baseModel 过滤到 Pony/Illustrious/Anima | 31（3 个模型族） | 90% | **0.811** |

### 18.2 A 批：低分几乎全是"分布外"，不是"画错了"

A 批 94 只手，20% 低于 0.5。把最低的 12 只连原图摆出来一看：

- 兔子、猫、水墨猫、山羊人 —— 检测器把**爪子/兽手**当成了手
- 写实人像照片、厚涂、水墨 —— 训练集里根本没有的画风

也就是说这 20% 低分主要是**分布外拒收**。对"只训练过动漫手"的模型来说，
这其实是合理行为，但**不能算作"检出画错"**。

按模型族拆：OpenAI 0.868 / Illustrious 0.941 / Anima 0.910 明显高于
Krea 2 0.614 与 Krea 2 Turbo 0.677 —— 因为后两者的样本大量是写实照片。
**同一个模型，画风越接近训练域分越高**，和第十七节的结论一致。

### 18.3 B 批：动漫族上模型是准的

41 只手（Pony 14 / Illustrious 23 / Anima 4），中位分 **0.811**，
低于 0.5 的 6 只（15%）。逐只放大看：

| 分数 | 实际内容 | 该不该低分 |
|---|---|---|
| 0.170 | 毛茸茸的尾巴 | 不是手，**检测器误检** |
| 0.277 | 白色麻花辫 | 不是手，**检测器误检** |
| 0.346 | 半写实手拿手机 | 结构成立，属分布外 |
| 0.464 | 贴地的手（重彩） | 结构成立，风格化 |
| 0.495 | 机械手臂 | 不是人手，**检测器误检** |
| 0.497 | 暗光下握杯的手 | 结构成立，欠曝 |
| 0.508 | 搭在毛上的手 | 结构成立 |
| 0.517 | 107px 暗块 | 太小无法判 |

**8 只里没有一只能指出客观结构缺陷。** 3 只根本不是手，其余是
分布外/欠曝/太小。真正的手里约有 4/22（≈18%）被压到 0.5 以下但没有可指认的缺陷
—— 这是补真实数据之后的残余误报（补之前是 29.8%，见 17.6）。

高分端是对的：0.95~1.00 那些确实是干净的动漫手。

### 18.4 ★ 这轮暴露的真问题：检测器才是短板

B 批 41 个"手"里，我人工数出**约 15~20 个根本不是手**
（毛尾巴、麻花辫、机器人臂、狐狸脸、猫、螃蟹钳、灯笼、花朵、护甲、暗块）。
而且模型给它们的分数是：

| 内容 | 质量分 |
|---|---|
| 灯笼 | 0.950 / 0.994 |
| 白色麻花辫 | 0.984 |
| 螃蟹钳 | 0.899 |
| 橘猫 | 0.831 |
| 狐狸脸 | 0.680 |

**质量模型没有"这不是手"这个输出。** 它只会回答"这只手画得好不好"，
所以任何像手的东西它都敢给 0.95。

而 `_predict.py` 现有的"检测置信度低但质量分高"冲突检查在这里没用 ——
检测器对灯笼、辫子给的是**高置信度**的框。

> 这正好印证了用户当初那句话：**"其实到了后期，hand_yolov8 可以被优化掉"**。
> 现在有了量化：在这批真实第三方图上，检测器报告的"手"里
> **约四成不是手**，而质量模型无法自救。

### 18.5 该怎么修（按性价比）

1. **给模型加第三个类：`not_hand`。** 现在已经有素材了 ——
   这轮 CivitAI 样本里就攒了十几只（灯笼/辫子/兽爪/机械臂/花），
   再按同样办法抓几百只很容易（检测器误检是稳定的，不会缺）。
   三分类后 `_predict.py` 可以直接把 not_hand 排掉，
   剩下 good/bad 的判断才有意义。这是**最该做的下一步**。
2. **或者在管线层加闸**：把手部裁剪的尺寸/长宽比/目标占比设阈值，
   明显不像手的直接丢。粗糙但立刻能用。
3. **换检测器**：hand_yolov8s 对非手物体的假阳性太高。
   但要重训检测器属于另一个项目了。

### 18.6 现状小结（截至第十八节）

| 环节 | 状态 |
|---|---|
| 质量模型在**真动漫手**上 | 可用。CivitAI 动漫族中位 0.811，高分端准确 |
| 质量模型在真实出图上的误报 | 2.1%（补数据后） |
| **检测器** | **明显短板**：第三方图上约四成"手"不是手 |
| 缺的三分类 | good / bad / **not_hand** ← 下一步 |

## 十九、修检测器假阳性：试了三种办法，最省钱的那个赢了

第十八节留下的问题：第三方图上检测器报告的"手"里约四成不是手，
而质量模型没有"这不是手"的输出，会照着 0.95 报出去。

### 19.1 素材：让检测器自己产出非手样本

不必凭空造。做法是从 CivitAI 抓图 → 跑 hand_yolov8s → **把它的检测框当候选**，
再人工判"是手 / 不是手"。假阳性是稳定可复现的，所以这类素材管够。

一共标了 **480 个候选**，其中 **168 个确认不是手**：

| 批次 | 检测阈值 | 候选 | 非手 | 假阳性率 |
|---|---|---|---|---|
| 第 1 批 | conf ≥ 0.35 | 240 | 65 | **27%** |
| 第 2 批 | conf ≥ 0.20（同 237 张图重跑） | 240 | 103 | **43%** |
| 合计 | | 480 | 168 | 35% |

非手都是些什么：树干、树叶、花、灯笼、麻花辫、兽爪、猫、螃蟹钳、
靴子、脚、眼睛、玻璃反光、雕刻手、护甲、编织物、水花。

### 19.2 办法一（失败）：直接改成三分类

最直接的想法是把输出头改成 `bad / good / not_hand` 三类共训。
**结果把主任务打坏了**：good/bad 的验证 AUC 从二分类的 0.833
掉到 **0.64~0.74**。

原因：not_hand 只有 65 只，类别权重被抬到 4.75，模型为了照顾这个小类，
挤掉了原本用来分辨 good/bad 的表征能力。**这条路否掉。**

### 19.3 办法二（平庸）：单独训一个 CNN 闸门

改成两段式：闸门判"是不是手"，是手再交给已有的 61 MB 集成打分。
这样完全不动已交付的质量模型，风险最小。

| not_hand 样本数 | 闸门 OOF AUC | 阈值 0.5 挡住非手 | 真手被误挡 |
|---|---|---|---|
| 65 只 | 0.8710 | 35.7% | 2.4% |
| **168 只** | **0.7532** | 35.7% | 2.4% |

样本变多 AUC 反而降了 —— 因为第二批（低检测阈值）带进来的是**更难的**样本
（浅色手、手套、爪甲、雕刻手）。而且用全量模型在这 65 只上测是 98.5% 挡住，
和交叉验证的 35.7% 差了一大截，说明小样本时严重过拟合。

**这说明"手/不是手"的边界本身是模糊的**：手套、护甲手、爪形手、
木雕手既像手又不像手。再堆数据也只能缓慢改善。

### 19.4 ★ 办法三（胜出）：直接用检测器置信度

回头量了一下免费信号 —— 检测器自己输出的置信度：

| 信号 | AUC |
|---|---|
| 裁剪尺寸 | 0.5433 |
| 训练的 CNN 闸门（168 只） | 0.7532 |
| **检测器置信度** | **0.9117** |

**检测器置信度单独用，比专门训一个模型还好。** 道理也简单：
它本来就是个手部检测器，它不确定的时候，多半就是因为那不是手。

阈值取舍（480 个候选上实测）：

| det 阈值 | 挡住非手 | 真手被误挡 | 非手残留 |
|---|---|---|---|
| 0.30 | 23.2% | 1.9% | 76.8% |
| 0.35 | 31.0% | 1.9% | 69.0% |
| **0.40** | **47.0%** | **3.8%** | **53.0%** |
| 0.45 | 53.0% | 6.4% | 47.0% |
| 0.50 | 63.7% | 9.3% | 36.3% |
| 0.60 | 79.8% | 12.5% | 20.2% |

**默认取 0.40**：挡住近一半假阳性，只误伤不到 4% 的真手，
而且**零成本** —— 不需要第二个模型、不增加推理时间、不占体积。

已接进 `_predict.py`：

```
python _predict.py --full <插画>              # 默认 min-det 0.40
python _predict.py --full <插画> --min-det 0.35   # 保守
python _predict.py --full <插画> --min-det 0.50   # 更狠
```

### 19.5 这一轮的教训

1. **先量免费基线，再训模型。** 我花了时间训三分类、训闸门，最后发现
   检测器早就把答案写在它的置信度里了。AUC 0.91 对 0.75。
2. **加类别不是免费的。** 三分类看起来"更完备"，实际把主任务
   AUC 从 0.83 打到 ~0.70。小类会偷走表征能力 —— 除非那个类样本足够。
3. **模糊的边界不能靠堆数据解决。** 手/非手在"手套、爪甲、雕刻手"上
   本来就分不清，这是定义问题不是数据问题。
4. 但那 480 个人工标注**没有白费**：正是它让我能量出 0.9117 这个基线，
   否则我永远不会想到去量检测器置信度。

### 19.6 现在管线的样子

```
插画
 └─ hand_yolov8s 检测（conf 0.20 捞全）
      └─ 闸门：det ≥ 0.40 才留下        ← 第十九节，挡掉约一半假阳性
           └─ 61 MB 集成打分           ← 第十二节，good/bad
                └─ 阈值（建议先跑 _calibrate.py 按自己的图定）
```

残留问题：仍有约一半假阳性会漏过去（det 高但不是手，比如灯笼 0.89）。
要彻底解决得换检测器或改三分类并补足样本 —— 那是另一个投入量级的事。

## 二十、补到 445 只非手后再试三分类：三种架构全都不行

第十九节因为 not_hand 只有 65 只，三分类把主任务打坏了。这一轮把样本补到
**445 只**，并把架构改了两次，结论是：**这条路不通，免费的 det 阈值才是对的。**

### 20.1 先把样本补到 445

CivitAI 恢复后又抓了 374 张新图（16 组 sort×period 组合、翻页 12 页），
检测阈值压到 0.20 榨假阳性，得到 644 个新候选。

这 644 格**交给子代理标**（机械二元判断，适合外包），它报了
hand 367 / not_hand 277（43%）。用它自己的统计做了两项校验：

| 校验 | 结果 |
|---|---|
| 程序化检查（644 条、无缺漏、无重复、全 int） | 通过 |
| 独立旁证：det 置信度能否预测它的判定 | **AUC 0.874**（我自己 480 条上是 0.9117）|
| 类别构成 | 抽象墨迹/纹理 55、植物 35、铠甲皮革 35、动物爪脚 30、布料 18… |

与我此前所见一致，采信。合计标注 **1124 个候选 → 445 只确认非手**。

### 20.2 三种架构，逐一看

| 方案 | good/bad AUC | not_hand 能力 | 代价 |
|---|---|---|---|
| 二分类（不动） | **0.8330** | — | — |
| 三分类 softmax，65 只非手 | 0.64~0.74 | — | 主任务崩 |
| 三分类 softmax，445 只 + sqrt 权重 | 0.7175 | 召回 52.6% | 主任务仍崩 |
| **两头多任务**（共享骨干，quality/hand 两个头） | **0.7437** | AUC **0.6382** | 主任务仍崩，且误伤 25% 真手 |
| 专用 CNN 闸门（mobilenet） | — | AUC **0.6873** | 0.5 阈值误伤 10.9% 真手 |
| **检测器置信度（免费）** | — | **AUC 0.9117** | 几乎为零 |

### 20.3 关键发现：不是样本不够，是任务在抢表征

专做"是不是手"的闸门，AUC 随着**数据变多反而下降**：

| not_hand 样本 | 闸门 AUC |
|---|---|
| 65 只 | 0.8710 |
| 168 只 | 0.7532 |
| **445 只** | **0.6873** |

不是标注变差了（旁证 AUC 0.874 说明标签可靠），而是**后补的样本越来越难**：
低检测阈值榨出来的是"浅色手、手套、爪甲、雕刻手、模糊手"这类
**本身就介于手与非手之间**的东西。

同时，只要把 not_hand 混进训练（无论 softmax 还是多头），
good/bad AUC 就从 0.833 掉到 0.72~0.74 —— 因为"这是不是手"是**低频的大形状判断**，
而"这手画得好不好"依赖**高频的细节**（指节、指甲、指缝）。
同一个骨干同时学这两件事，粗粒度特征会把细粒度特征挤掉。

**两头多任务也没救**：虽然把两个损失解耦了，但共享骨干这一点没变，
且 head_h 反过来还更差（0.638 < 0.687），说明加了 quality 监督之后
"是不是手"反而更难学 —— 两个任务的最优特征互相冲突。

### 20.4 所以最终方案没变，而且更确定

```
插画
 └─ hand_yolov8s 检测
      └─ det ≥ 0.40 挡住约一半假阳性（约 3.8% 真手代价）
           └─ 61 MB 集成打分（good/bad，AUC 0.8664）
                └─ 阈值按自己的图用 _calibrate.py 定
```

`_predict.py --min-det` 默认 0.40 已在第十九节接好，这一轮不改。

### 20.5 一个仍未被利用的发现

三分类/多任务模型在 **det ≥ 0.40 那 221 个"免费闸门挡不住"的非手**上
能挡住 **56.6%** —— 这确实是 det 阈值拿不到的信息。
但代价是真手被误挡 **25%**，完全不划算。
要让这条真正可用，得让 head_h 在不牺牲 quality 的前提下学好 ——
也许要**两个完全独立的模型**（不共享骨干），并且 not_hand 样本
质量更高（排除那些"本来就是手但画得怪"的样本）。这是下一步可选方向，
不是当前该做的事。

### 20.6 这一轮花掉的与换来的

- 花掉：抓 374 张图 + 标 1124 个候选（其中 644 格外包给子代理）
- 换来：**确认了一条错误路线**，以及一份 1124 条的 hand/not_hand 标注集
  （`_nothand/`，445 只非手），以后换检测器或改架构可以直接复用
- 没有换来：更好的管线。管线还是 det 阈值 + 质量模型

> 连续两轮都在同一个地方撞墙，原因一致：**我在试图用一个小 CNN
> 去替代检测器自己的置信度**，而检测器在这一项上本来就比它强。
> 后面如果再要做，应该先问"有没有现成的信号比训练模型更便宜更好"。
