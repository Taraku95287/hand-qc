# 五个比 AUC 更值钱的发现

**简体中文** | [English](FINDINGS.md)

这个项目产出的东西里，分类器是最没意思的一件。下面这些结果改掉了我对这个任务的理解，每一条都附上背后的测量。数字复现自 `RESULTS.zh-CN.md` / `scripts/evaluate.py`。

---

## 1. 标注几乎经不起重新推导

整个项目立在 862 张人工标注的裁剪图上。所以我先测 `bad` 标签能不能复现：同一批手、重新过一遍、看不到原始结论，分三档（`fine` / `questionable` / `wrong`），并且对 `wrong` 要求从五条标准里点出具体一条。

| 186 个 `bad` 标签的复核结果 | 占比 |
|---|---:|
| 能复现为某个具体的结构性错误 | **2%** |
| 第二遍被判为 `fine` | **81%** |
| 干净子集上的一致程度，Cohen's κ | **−0.003** |

κ ≈ 0 意味着这两遍之间的一致程度，和随便两个标注者凑一起差不多。模型的 0.8664 AUC 忠实复现的是*某一次*标注的边界。它不是在测量手画得对不对，而且再加多少训练数据也变不成那个测量。

**后果：** 我不再说它是错误检测器，改口叫它审美过滤器。同一次复核还给出了诚实的基率 —— 客观画坏的手约占真实生成图的 **2%**，不是大家默认的那个「AI 不会画手」的数字。三轮想把错误率顶上去的尝试（11 组生成配置、68 个样本）在当前动漫底模上产出**零**张结构性画坏的手。

要把标注修好，至少得做到：≥3 位独立标注者、每种手势一份书面标准、报一致性矩阵而不是单一准确率。这里都没做。

## 2. 按 CV 分数挑骨干就是抛硬币，而我是意外证明的

第一次实验：`resnet34` 是最好的骨干（0.8057），`resnet18` 第二（0.8156），所以看起来该选 `resnet34`。同一份代码、同一份数据，给增强的 RNG 设上种子重跑：0.8107 对 0.8330 —— **排名反过来了。**

原因是增强用了一个没设种子的全局 `np.random`。同一份代码跑两遍相差 **>0.01 AUC**，有个下游指标（跨模型误报率）在 **84% 和 0%** 之间来回。

种子固定之后，四个骨干落在 0.8107 / 0.8289 / 0.8330 / 0.8567 —— 从 1.53 M 到 21.30 M 参数的四种架构，跨度只有 0.046。

**后果：** 把发布模型从 0.8330 抬到 0.8664 的那 +0.033，来自*集成两个家族*，不是来自架构选择。在这个区间里，任何单次运行的骨干对比都该先当成噪声，直到跨种子重复过。这个仓库每个产物都在 `.npz` 里带着 `seed` 和 `select`，原因就是这个。

## 3. 固定阈值量的是校准，不是判别力

有一阵子这个仓库声称 `resnet34`「记住了 Illustrious 的画风」，理由是它在一个没见过的模型家族上把 84% 的好手报了出来。并没有。固定种子重跑之后，这个数字是 **0%**。

两次运行的判别力相同。不同的是分数分布落在哪里：第一次运行里，未见家族的好手中位分是 0.244；第二次是 1.000。阈值固定成 0.5，就把*校准*上的差异变成看起来像*能力*上的差异。

修法：把每个模型对齐到同一个域内工作点（拒掉 15% 的域内好手），再比。对齐之后，表里最差的模型是它域内误报率的 1.7×，发布的集成是 0.0×。没有任何东西在记画风。

**后果：** 任何用固定切点做的跨域比较，量的都是运气。这也是 `predict.py` 要收 `--threshold`、`calibrate.py` 之所以存在的原因 —— 也是这次撤回还摆在 `HAND_QUALITY.md` §12.2b 里、没有悄悄删掉的原因。

## 4. 域内 AUC 对真正要紧的失效近乎失明

把 86 张来自真实用户作品的手部裁剪图加进 776 张的训练集：

| | 加之前 | 加之后 |
|---|---:|---:|
| 域内 OOF AUC | 0.8678 | 0.8664 (**−0.001**) |
| 真实好手上的分数平移 | −0.258 | +0.008 |
| 真实好手上的误报 | **29.8%** | **2.1%** |

核心指标*略微变差*，工具却从「每十张好图标错三张」变成能用。在训练分布上做交叉验证的 AUC 看不见这件事，因为漂移发生在输入分布上，不在模型里。

**后果：** 对过滤器来说，与部署相关的数字是目标分布上的误报率，而且必须在那条分布上测。多 10% 来自正确位置的数据，比任何建模改动都管用。这也意味着，简历或模型卡上单写一个「AUC 0.87」，旁边不附平移测量，几乎等于没给信息。

## 5. 免费信号打赢了专门训练来替代它们的模型

手部检测器在第三方画作上返回的框里，大约 40% 不是手。我先把两个门控模型都训了，才回头去看手上已经有的东西。

| 手 vs 非手，480 张已标注裁剪图（168 张非手） | AUC |
|---|---:|
| 裁剪框尺寸 | 0.5433 |
| 为此专门训的 CNN 门控（168 张样本） | 0.7532 |
| 多任务手部头（更大的数据集，445 张非手） | 0.6873 |
| **检测器原始置信度** | **0.9117** |

检测器自己的置信度胜出，而且免费：不用第二个模型、不用多跑一次推理、不多占一个字节。手部检测器的不确定性*本身就是*一个手/非手分类器。在 `--min-det 0.40` 下，它挡掉 47% 的非手，只损失 3.8% 的真手。

同一轮的另一个失效：把模型改成 3 分类（`good / bad / not_hand`），反而把它本该改善的任务搞塌了，good/bad AUC 从 0.833 掉到 **0.64–0.74**，因为 65 张非手样本带着 4.75 的类别权重，把主任务的表征抢走了。多一个类别不是免费的，哪怕它看起来更正确。

**后果：** 训一个组件之前，先量一下它最便宜的那个信号。这里这一步被跳过两次，两次训出来的模型都不如桌上现成的东西。

---

## 合起来是什么

最初提的那个任务 —— *「检测画错的手」* —— 定义不足。有意思的工程不在分类器，而在：

1. 先确认这个目标到底可不可测（发现 1），
2. 把模型能力与校准漂移分开（发现 2 和 3），
3. 在要紧的那条分布上测，而不是在你手上有的那条上测（发现 4），
4. 在有反证之前，优先用免费信号而不是训出来的（发现 5）。

最后到底还是出来一个站得住的工具 —— 61 MB、0.8664 OOF AUC、重新校准后真实画作上 2.1% 误报 —— 但正因为上面这些，它附带 `calibrate.py`、一节诚实的局限说明，以及一个写明了的适用范围：「triage filter」。
